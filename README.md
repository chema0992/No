# No

**No는 편의 기능보다 제약을, 문자보다 바이트를 우선하는 최소주의 텍스트 에디터입니다.**

일반적인 텍스트 에디터처럼 문서 전체를 메모리에 올리거나, 커서와 여러 편의 기능을 제공하는 것을 목표로 하지 않습니다. No는 파일을 **16바이트 컨텍스트(context)** 단위로 다루며, 편집 중에는 현재 컨텍스트만 메모리 버퍼에 보관합니다.

## 특징

- **16바이트 컨텍스트**: 파일을 16바이트씩 나누어 다룹니다. 줄바꿈도 1바이트로 계산합니다.
- **바이트 단위 편집**: 글자나 유니코드 문자가 아니라 바이트가 작업 단위입니다.
- **최소한의 명령어**: 위치 선택, 바이트 출력, 삽입, 삭제, 컨텍스트 이동, 저장, 종료만 제공합니다.
- **편집 중 즉시 파일을 다시 쓰지 않음**: `i`와 `d`는 현재 컨텍스트의 메모리 버퍼만 수정합니다. 실제 저장은 `w`를 실행할 때 이루어집니다.
- **저장 후 종료**: `w`는 파일을 저장하고 에디터를 종료합니다.
- **실패 시 조용히 종료**: 잘못된 명령이나 처리할 수 없는 상태에서는 저장을 시도한 뒤 종료합니다. 저장 자체가 실패하면 실패 코드로 종료합니다.

## 빌드

GCC가 설치된 Linux 환경을 기준으로 합니다.

기본적으로 레포지토리에 일반적인 빌드로 컴파일된 바이너리가 있습니다.

아래 코드는 일반적인 빌드입니다.

```sh
gcc -O2 -o no main.c
```

아래 코드는 RAM 점유율을 줄이기 위해 한 빌드입니다.

```sh
gcc -Os -s -ffunction-sections -fdata-sections -fno-ident -fno-asynchronous-unwind-tables -Wl,--gc-sections -static main.c -o no
```

## 실행

```sh
./no 파일이름
```

예를 들어:

```sh
./no test.txt
```

현재 구현은 **이미 존재하고 읽을 수 있는 파일**을 엽니다. 파일이 없거나 열 수 없으면 종료합니다.

## 명령어

위치는 현재 컨텍스트 안에서 지정합니다. `N`은 1부터 시작하는 바이트 번호입니다.

| 명령어 | 동작 |
|---|---|
| `Nb` | 현재 컨텍스트의 N번째 바이트를 선택합니다. 예: `6b` |
| `p` | 선택한 바이트 하나를 출력하고 줄바꿈합니다. |
| `d` | 선택한 바이트 하나를 삭제합니다. |
| `iS` | 바이트 하나를 삽입합니다. 예: `iA` |
| `i\n` | 줄바꿈 바이트를 삽입합니다. |
| `i\xHH` | 16진수 `HH`로 지정한 바이트를 삽입합니다. 예: `i\x41`은 `A`에 해당하는 바이트입니다. |
| `nr` | 다음 컨텍스트로 이동합니다. |
| `nl` | 이전 컨텍스트로 이동합니다. |
| `w` | 변경 내용을 저장하고 종료합니다. |
| `q` | 저장하지 않고 종료합니다. |

### 위치와 삽입 규칙

- `Nb`의 `N`은 **바이트 번호**입니다. `6b`는 여섯 번째 바이트를 선택합니다.
- `iS`는 `S`에 해당하는 바이트 하나를 삽입합니다. 바이트를 선택한 상태라면 선택한 바이트 **뒤에** 삽입하며, 위치가 선택되지 않았다면 맨 앞에 삽입합니다.
- `d`로 바이트를 삭제하면 현재 컨텍스트 안의 뒤쪽 바이트가 앞으로 이동합니다. 다른 컨텍스트의 바이트를 편집 중에 끌어오지는 않습니다.
- 삽입 후 컨텍스트 길이가 16바이트를 넘는 삽입은 허용되지 않습니다.

### 컨텍스트 이동과 종료 규칙

- `nr`과 `nl`은 컨텍스트 단위로 이동합니다.
- 현재 컨텍스트를 수정한 상태에서 `nr` 또는 `nl`을 실행하면 이동하지 않고 저장 후 종료합니다.
- 파일의 처음이나 끝을 넘어가려는 경우에도 저장 후 종료합니다.
- 잘못된 명령이나 유효하지 않은 위치 등 처리할 수 없는 상태에서도 저장을 시도한 뒤 종료합니다.
- `q`만은 저장하지 않고 종료합니다.

## 바이트 단위 편집

No는 일반적인 의미의 UTF-8 문자 편집기가 아닙니다. **문자가 아니라 바이트를 편집합니다.**

UTF-8에서 한글은 보통 여러 바이트로 인코딩되므로, 한글 한 글자의 일부 바이트만 출력하거나 삭제할 수 있습니다. 이 경우 터미널에 문자가 깨져 보이거나 파일의 UTF-8 인코딩이 손상될 수 있습니다. 이는 문자 단위 편집 기능을 제공하지 않는 현재 설계의 결과입니다.

> No는 UTF-8 문자를 편집하지 않습니다. 바이트를 편집합니다.

## No 라인업 구상

현재 기본판인 **No**를 중심으로 다음과 같은 라인업을 구상하고 있습니다.

| 이름 | 실행 명령 | 방향 |
|---|---|---|
| **No** | `no 파일이름` | 기본판. 핵심 구현이며 가장 활발하게 업데이트합니다. |
| **No Pro** | `nop 파일이름` | 편의 기능을 추가한 버전입니다. 더 무거우며 No의 최소주의 철학에서 가장 멀어집니다. |
| **No Lite** | `nol 파일이름` | RAM 점유율을 줄이면서 속도는 유지하는 것을 목표로 합니다. |
| **No Sys** | `nos 파일이름` | 4바이트 컨텍스트, 컨텍스트 하나만 로드, 시스템콜 사용을 목표로 하는 초경량 실험판입니다. 속도보다 메모리 최소화를 우선합니다. |

### 업데이트 우선순위

1. **No**: 핵심 구현을 가장 활발하게 업데이트합니다.
2. **No Pro**: 편의 기능을 개발합니다.
3. **No Lite**: 메모리 사용량을 줄이는 방향으로 최적화합니다.
4. **No Sys**: 기능 추가 없이 버그 수정 위주로 유지합니다.

No Lite, No Sys, No Pro의 세부 구현과 제공 여부는 각 버전의 개발 상황에 따라 달라질 수 있습니다.

## 설계 철학

No는 모든 불편함을 해결하려는 에디터가 아닙니다. 일부러 기능을 제한하고, 작업 단위를 작게 유지하며, 메모리 사용을 통제하는 실험입니다.

**기능을 무작정 늘리기보다, 정해 둔 제약을 지키는 것 역시 No의 설계 목표입니다.**

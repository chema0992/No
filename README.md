# No 🗿

> **A text editor that says “No” to convenience.**

No는 편의 기능보다 제약을, 문자보다 바이트를 우선하는 최소주의 텍스트 에디터입니다.

일반적인 텍스트 에디터처럼 파일 전체를 메모리에 올리거나 커서, 검색, 실행 취소 같은 기능을 제공하는 것을 목표로 하지 않습니다. 대신 파일을 작은 **컨텍스트(context)** 단위로 나누고, 편집 중에는 현재 컨텍스트를 중심으로 동작합니다.

No 패밀리는 단순히 기능이 많은 에디터를 만드는 프로젝트가 아닙니다.

**얼마나 적은 메모리와 얼마나 적은 기능으로 파일을 편집할 수 있는가?**

No는 이 질문을 실제 코드로 실험합니다. 🔧

---

## 🧭 설계 철학

- **바이트가 작업 단위입니다.** 문자가 아니라 바이트를 선택하고, 삽입하고, 삭제합니다.
- **메모리를 작게 유지합니다.** 파일 전체를 메모리에 올리는 대신 현재 컨텍스트를 중심으로 동작합니다.
- **기능을 의도적으로 제한합니다.** 검색, 복사·붙여넣기, 실행 취소 같은 일반적인 편의 기능은 기본 설계에 포함하지 않습니다.
- **실패에도 조용합니다.** 잘못된 명령이나 처리할 수 없는 상태에서는 저장을 시도한 뒤 종료합니다. 저장에 실패하면 실패 상태로 종료합니다.
- **버전마다 목표가 다릅니다.** 기본형, 초저메모리형, 편의 기능 중심의 확장형을 구분합니다.

> No는 모든 불편함을 없애려는 에디터가 아닙니다. 일부 불편함을 설계의 일부로 남겨 둡니다.

## 📦 프로젝트 구조

```text
.
├── src/
│   ├── no.c       # No 기본판 소스
│   └── nos.c      # No Sys 초저메모리판 소스
├── e/
│   ├── no         # 미리 컴파일된 No 실행 파일
│   └── nos        # 미리 컴파일된 No Sys 실행 파일
├── README.md
├── .gitignore
└── LICENSE        # MIT License
```

`e/`에는 미리 컴파일된 `no`와 `nos` 실행 파일이 있습니다. 직접 빌드하지 않고 실행 파일을 사용하려면 해당 파일을 이용할 수 있습니다.

현재 제공되는 미리 컴파일된 바이너리는 **x86-64 아키텍처 및 Ubuntu 환경을 기준으로 빌드**되었습니다. 다른 운영체제, 아키텍처 또는 libc 환경에서는 실행되지 않을 수 있습니다. 각 환경에 맞게 직접 빌드하는 것을 권장합니다.

## 🧩 라인업

| 버전 | 상태 / 실행 명령 | 방향 |
|---|---|---|
| **No** | 기본판 · `no 파일이름` | 16바이트 컨텍스트를 사용하는 핵심 구현입니다. 기본적인 바이트 편집 기능과 비교적 높은 이식성을 목표로 합니다. |
| **No Sys** | 초저메모리판 · `nos 파일이름` | 4바이트 컨텍스트와 저수준 파일 디스크립터 I/O를 사용합니다. 메모리 최소화를 우선하며 편집 기능도 더 제한적입니다. |
| **No Pro** | 향후 구상 | 편의 기능을 추가하는 확장판입니다. 더 많은 기능을 제공하는 대신 메모리 사용량과 구현 복잡도가 커질 수 있습니다. |

### 🛠️ 업데이트 방향

1. **No**: 핵심 구현을 가장 활발하게 개선합니다.
2. **No Pro**: 개발을 시작하면 편의 기능을 추가합니다.
3. **No Sys**: 새로운 기능보다 버그 수정과 안정성 유지에 집중합니다.

## 🛠️ 빌드

기본 빌드 예시는 Linux 환경을 기준으로 합니다. 소스 파일은 `src/`에 있으므로 아래 명령은 저장소 루트에서 실행하면 됩니다.

현재 권장 빌드는 **`-Oz` 최적화**를 사용합니다. `-Oz`는 실행 속도보다 코드 크기를 더 적극적으로 줄이는 데 초점을 둡니다. 컴파일러 버전에 따라 `-Oz`를 지원하지 않을 수 있습니다.

아래 명령은 예시이며, 사용 환경과 목적에 맞게 컴파일 옵션을 변경해도 됩니다.

### No

```sh
gcc -Oz -s -ffunction-sections -fdata-sections -fno-ident -fno-asynchronous-unwind-tables -Wl,--gc-sections -static src/no.c -o no
```

### No Sys

가능하면 **`musl-gcc`를 사용하는 빌드를 권장**합니다.

```sh
musl-gcc -Oz -s -ffunction-sections -fdata-sections -fno-ident -fno-asynchronous-unwind-tables -Wl,--gc-sections -static src/nos.c -o nos
```

Debian 계열 배포판에서는 다음 명령으로 `musl-gcc`를 설치할 수 있습니다.

```sh
sudo apt install musl-tools
```

`musl-gcc`가 없다면 일반 `gcc`로 빌드를 시도할 수 있습니다. 다만 컴파일러와 libc 구현에 따라 경고 또는 동작 차이가 발생할 수 있습니다.

### 🪟 Windows에서 No 빌드하기

No 기본판은 Windows의 GCC 환경에서도 빌드할 수 있습니다. 예를 들어 MinGW 계열 GCC를 사용하는 경우:

```powershell
gcc -O2 src/no.c -o no.exe
.\no.exe test.txt
```

No는 GUI 프로그램이 아니라 터미널에서 실행하는 CLI 프로그램입니다. 파일 이름을 인자로 전달해야 하므로 실행 파일을 더블클릭하는 방식은 지원하지 않습니다.

No Sys는 Linux 저수준 I/O에 의존하므로 Windows에서의 직접 빌드를 대상으로 하지 않습니다.

## ▶️ 실행

Linux:

```sh
./no 파일이름
./nos 파일이름
```

예시:

```sh
./no test.txt
./nos test.txt
```

Windows에서 No를 빌드한 경우:

```powershell
.\no.exe test.txt
```

현재 두 버전 모두 기본적으로 **이미 존재하고 읽을 수 있는 파일**을 엽니다. 파일이 없거나 열 수 없으면 종료합니다.

`no 파일이름`처럼 경로 지정 없이 실행하려면 실행 파일이 `PATH`에 등록된 디렉터리에 있어야 합니다. 저장소 루트에 있는 실행 파일은 `./no` 또는 `./nos`처럼 실행하는 것을 권장합니다.

## ⌨️ 명령어

명령은 터미널에서 입력합니다. 위치 선택 명령의 `N`은 현재 컨텍스트 안에서 1부터 시작하는 바이트 번호입니다.

### 🟦 No

No는 **16바이트 컨텍스트**를 사용합니다.

| 명령어 | 동작 |
|---|---|
| `Nb` | 현재 컨텍스트의 N번째 바이트를 선택합니다. 예: `6b` |
| `p` | 선택한 바이트를 그대로 출력합니다. 자동으로 줄바꿈을 추가하지 않습니다. |
| `d` | 선택한 바이트를 삭제합니다. |
| `iX` | 바이트 `X`를 삽입합니다. |
| `i\n` | 줄바꿈 바이트를 삽입합니다. |
| `i\xHH` | 16진수 `HH`에 해당하는 바이트를 삽입합니다. 예: `i\x41`은 `A`입니다. |
| `nr` | 다음 컨텍스트로 이동합니다. |
| `nl` | 이전 컨텍스트로 이동합니다. |
| `m` | 파일의 마지막 컨텍스트가 가득 찬 경우 새 컨텍스트를 만듭니다. |
| `w` | 변경 내용을 저장하고 종료합니다. |
| `q` | 저장하지 않고 종료합니다. |

- `iX`는 바이트 하나를 삽입합니다. 선택한 바이트가 있으면 그 뒤에 삽입하고, 선택하지 않았다면 맨 앞에 삽입합니다.
- 컨텍스트는 최대 16바이트입니다. 컨텍스트가 가득 찬 상태에서 삽입을 시도하거나, 현재 컨텍스트를 수정한 상태에서 이동을 시도하는 등 허용되지 않는 상황에서는 저장을 시도한 뒤 종료합니다.
- `nr` 또는 `nl`로 파일의 범위를 벗어나려는 경우에도 저장을 시도한 뒤 종료합니다.
- `p`는 선택한 바이트를 추가 가공 없이 출력합니다. 선택한 바이트 자체가 줄바꿈(`\n`)인 경우에는 해당 바이트의 특성에 따라 줄이 바뀔 수 있습니다.
- No는 UTF-8 문자 단위 편집기가 아닙니다. 한글 등 멀티바이트 문자의 일부 바이트를 편집하면 문자가 깨질 수 있습니다.

### 🟥 No Sys

No Sys는 **4바이트 컨텍스트**를 사용합니다. 저수준 파일 디스크립터 I/O를 활용하며, 편집 중 한 번에 하나의 컨텍스트만 메모리에 유지하는 초저메모리 실험판입니다.

| 명령어 | 동작 |
|---|---|
| `Nb` | 현재 컨텍스트의 N번째 바이트를 선택합니다. 예: `2b` |
| `d` | 선택한 바이트를 삭제합니다. |
| `iX` | 바이트 `X`를 삽입합니다. |
| `i\n` | 줄바꿈 바이트를 삽입합니다. |
| `i\xHH` | 16진수 `HH`에 해당하는 바이트를 삽입합니다. |
| `n` | 다음 컨텍스트로 이동합니다. |
| `m` | 파일의 마지막 컨텍스트가 가득 찬 경우 새 컨텍스트를 만듭니다. |
| `w` | 저장하고 종료합니다. |

- No Sys에는 `p`, `q`, `nl` 명령이 없습니다.
- `n`은 현재 컨텍스트가 가득 차 있고 수정되지 않은 상태에서 다음 컨텍스트가 있을 때 사용할 수 있습니다.
- `m`은 현재 컨텍스트가 가득 찬 마지막 컨텍스트일 때만 사용할 수 있습니다.
- `iX`의 삽입 규칙은 No와 같습니다. 선택한 바이트 뒤에 삽입하며, 선택하지 않았다면 맨 앞에 삽입합니다.
- No Sys는 초저메모리 목표를 위해 명령과 편집 기능을 의도적으로 제한합니다.

## 📊 메모리 사용량 벤치마크

아래 값은 Linux 환경에서 `ps`로 관측한 **RSS(Resident Set Size)**입니다. 단위는 KiB이며, 두 프로그램 모두 `-Oz` 빌드 기준입니다.

| 테스트 파일 크기 | No RSS | No Sys RSS |
|---:|---:|---:|
| 16 B | 72 KiB | 36 KiB |
| 1 KB | 76 KiB | 40 KiB |
| 1 MB | 72 KiB | 36 KiB |
| 1 GB | 72 KiB | 40 KiB |

### 🔍 측정 결과 해석

- 반복 측정에서 No는 약 **72–76 KiB** RSS를 보였습니다.
- 반복 측정에서 No Sys는 약 **36–40 KiB** RSS를 보였습니다.
- 두 버전 모두 16바이트 파일부터 1GB 파일까지 파일 크기가 커져도 RSS가 거의 일정한 범위에 머물렀습니다.
- No Sys에서는 초기 단일 측정에서 **12 KiB**가 관측되기도 했습니다. 다만 반복 측정에서 같은 값이 재현되지는 않았으므로, 위 표에는 반복 측정에서 확인한 범위를 기록했습니다.

RSS는 프로세스의 실제 메모리 사용량을 이해하는 데 유용한 지표지만, 실행 시점과 페이지 상주 상태 등에 따라 값이 달라질 수 있습니다. 따라서 위 수치는 특정 Linux 테스트 환경에서 얻은 참고 결과이며, 모든 시스템에서 동일하게 재현된다는 보장은 없습니다.

> 📌 **핵심 관찰:** 테스트한 파일 크기가 16 B에서 1 GB로 증가해도 두 버전의 RSS는 거의 일정한 범위에 머물렀습니다. 파일 전체를 메모리에 올리지 않는 No 패밀리의 설계 방향을 보여주는 결과입니다.

# No 🗿

> **A text editor that says “No” to convenience.**

No는 편의 기능보다 제약을, 문자보다 바이트를 우선하는 최소주의 텍스트 에디터입니다.

일반적인 텍스트 에디터처럼 파일 전체를 메모리에 올리거나, 커서·검색·실행 취소 같은 기능을 제공하는 것을 목표로 하지 않습니다. No는 파일을 작은 **컨텍스트(context)** 단위로 나누고, 편집 중에는 현재 컨텍스트만 메모리에 보관합니다.

No 패밀리는 단순히 기능이 많은 에디터를 만드는 프로젝트가 아닙니다. **얼마나 적은 메모리와 얼마나 적은 기능으로 파일을 편집할 수 있는가**를 탐구하는 실험입니다. 🔧

## 🧭 설계 철학

- **바이트가 작업 단위입니다.** 문자가 아니라 바이트를 선택하고 삽입하고 삭제합니다.
- **메모리를 작게 유지합니다.** 파일 전체를 메모리에 올리는 대신 현재 컨텍스트를 중심으로 동작합니다.
- **기능을 의도적으로 제한합니다.** 검색, 복사·붙여넣기, 실행 취소 같은 일반적인 편의 기능은 기본 설계에 포함하지 않습니다.
- **실패에도 조용합니다.** 잘못된 명령이나 처리할 수 없는 상태에서는 저장을 시도한 뒤 종료합니다. 저장이 실패하면 실패 코드로 종료합니다.
- **버전마다 목표가 다릅니다.** 기본형, 초저메모리형, 편의 기능 중심의 확장형을 구분합니다.

> No는 불편함을 모두 없애려는 에디터가 아닙니다. 일부 불편함을 설계의 일부로 남겨 둡니다.

## 📦 프로젝트 구조

```text
.
├── src/
│   ├── no.c       # No 기본판 소스
│   └── nos.c      # No Sys 초저메모리판 소스
├── e/
│   ├── no         # 미리 컴파일된 No 실행 파일
│   └── nos        # 미리 컴파일된 No Sys 실행 파일
├── README.md
├── .gitignore
└── LICENSE        # MIT License
```

`e/`에는 미리 컴파일된 `no`와 `nos` 실행 파일이 있습니다. 직접 빌드하지 않고 실행 파일을 사용하려면 해당 파일을 이용할 수 있습니다. x86-64 아키텍처와 Ubuntu에서 컴파일 되었으므로, 실행 파일은 빌드 환경과 시스템 아키텍처에 따라 실행 가능 여부가 달라질 수 있습니다.

## 🧩 라인업

| 버전 | 상태 / 실행 명령 | 방향 |
|---|---|---|
| **No** | 기본판 · `no 파일이름` | 16바이트 컨텍스트를 사용하는 핵심 구현입니다. 기본적인 바이트 편집 기능을 제공합니다. |
| **No Sys** | 초저메모리판 · `nos 파일이름` | 4바이트 컨텍스트와 저수준 파일 디스크립터 I/O를 사용합니다. 메모리 최소화를 우선하며, 편집 기능도 더 제한적입니다. |
| **No Pro** | 향후 구상 | 편의 기능을 추가하는 확장판입니다. 더 무거워질 수 있으며, No의 최소주의 철학에서는 가장 멀어지는 버전입니다. |

(`no 파일이름` 처럼 ./를 안 붙일 경우엔 /usr/local/bin으로 파일을 옮기거나 터미널 프로필에 `export PATH=$PATH:.`
를 추가해야합니다.)

**이전 No Lite는 현재 라인업에서 제외했습니다.** No Sys가 이미 별도의 초저메모리 목표를 맡고 있어, 중간 단계인 Lite를 별도로 유지할 필요가 적다고 판단했습니다.

### 업데이트 방향

1. **No**: 핵심 구현을 가장 활발하게 개선합니다.
2. **No Pro**: 개발을 시작하면 편의 기능을 추가합니다.
3. **No Sys**: 새로운 기능보다 버그 수정과 안정성 유지에 집중합니다.

## 🛠️ 빌드

Linux 환경과 gcc와 musl-gcc가 있음을 기준으로 합니다. (musl-gcc는 데비안 계열 기준 `sudo apt install musl-tools` 를 하시면 설치가 됩니다)

소스 파일은 `src/`에 있으므로 아래 명령은 저장소 루트에서 실행하면 됩니다.
컴파일 코드는 예시이며, 필요 시 자기 입맛대로 컴파일 하시면 됩니다.

### No

```sh
gcc -Os -s -ffunction-sections -fdata-sections -fno-ident -fno-asynchronous-unwind-tables -Wl,--gc-sections -static src/no.c -o no
```

### No Sys

가능하면 **`musl-gcc`를 사용하는 빌드를 권장**합니다.

```sh
musl-gcc -Os -s -ffunction-sections -fdata-sections -fno-ident -fno-asynchronous-unwind-tables -Wl,--gc-sections -static src/nos.c -o nos
```

`musl-gcc`가 없다면 일반 `gcc`로도 빌드를 시도할 수 있습니다. 다만 컴파일러와 libc 구현에 따라 경고가 달라질 수 있으므로, 권장 빌드 환경에서는 위의 `musl-gcc` 명령을 사용하세요.

## ▶️ 실행

```sh
./no 파일이름
./nos 파일이름
```

예시:

```sh
./no test.txt
./nos test.txt
```

현재 두 버전 모두 기본적으로 **이미 존재하고 읽을 수 있는 파일**을 엽니다. 파일이 없거나 열 수 없으면 종료합니다.

## ⌨️ 명령어

### No

No는 **16바이트 컨텍스트**를 사용합니다. 위치 번호 `N`은 현재 컨텍스트 안에서 1부터 시작하는 바이트 번호입니다.

| 명령어 | 동작 |
|---|---|
| `Nb` | 현재 컨텍스트의 N번째 바이트를 선택합니다. 예: `6b` |
| `p` | 선택한 바이트를 출력하고 줄바꿈합니다. |
| `d` | 선택한 바이트를 삭제합니다. |
| `iX` | 바이트 `X`를 삽입합니다. |
| `i\n` | 줄바꿈 바이트를 삽입합니다. |
| `i\xHH` | 16진수 `HH`에 해당하는 바이트를 삽입합니다. 예: `i\x41`은 `A`입니다. |
| `nr` | 다음 컨텍스트로 이동합니다. |
| `nl` | 이전 컨텍스트로 이동합니다. |
| `w` | 변경 내용을 저장하고 종료합니다. |
| `q` | 저장하지 않고 종료합니다. |

- `iX`는 바이트 하나를 삽입합니다. 선택한 바이트가 있으면 그 뒤에 삽입하고, 선택하지 않았다면 맨 앞에 삽입합니다.
- 컨텍스트는 최대 16바이트입니다. 컨텍스트가 가득 찼거나 현재 컨텍스트를 수정한 상태에서 이동을 시도하는 등 허용되지 않는 상황에서는 저장을 시도한 뒤 종료합니다.
- No는 UTF-8 문자 단위 편집기가 아닙니다. 한글 등 멀티바이트 문자의 일부 바이트를 편집하면 문자가 깨질 수 있습니다.

### No Sys

No Sys는 **4바이트 컨텍스트**를 사용합니다. 저수준 파일 디스크립터 I/O를 활용하고, 한 번에 하나의 컨텍스트만 메모리에 올리는 초저메모리 실험판입니다. 출력 명령이나 저장하지 않고 종료하는 명령은 제공하지 않습니다.

| 명령어 | 동작 |
|---|---|
| `Nb` | 현재 4바이트 컨텍스트의 N번째 바이트를 선택합니다. 예: `2b` |
| `d` | 선택한 바이트를 삭제합니다. |
| `iX` | 바이트 `X`를 삽입합니다. |
| `i\n` | 줄바꿈 바이트를 삽입합니다. |
| `i\xHH` | 16진수 `HH`에 해당하는 바이트를 삽입합니다. |
| `n` | 다음 컨텍스트로 이동합니다. |
| `m` | 파일의 마지막 컨텍스트가 꽉 차 있을 때 새 컨텍스트를 만듭니다. |
| `w` | 저장하고 종료합니다. |

- No Sys에는 `p`, `q`, `nl` 명령이 없습니다.
- `n`은 현재 컨텍스트가 가득 차 있고 수정되지 않은 상태에서 다음 컨텍스트가 있을 때 사용할 수 있습니다.
- `m`은 현재 컨텍스트가 가득 찬 마지막 컨텍스트일 때만 사용할 수 있습니다.
- `iX`의 삽입 규칙은 No와 같습니다. 선택한 바이트 뒤에 삽입하며, 선택하지 않았다면 맨 앞에 삽입합니다.

## 📊 메모리 사용량 벤치마크

다음은 Linux에서 `ps`로 관측한 RSS 값입니다. 단위는 KB이며, 빌드 옵션과 실행 환경에 따라 수치가 달라질 수 있습니다.

| 테스트 파일 크기 | No RSS (KB) | No Sys RSS (KB) |
|---:|---:|---:|
| 16 B | 668 | 40 |
| 1 KB | 672 | 40 |
| 1 MB | 668 | 40 |
| 1 GB | 672 | 40 |

이 측정에서 No Sys는 16B 파일과 1GB 파일 모두 약 40KB RSS를 보였습니다. 파일 전체를 메모리에 올리지 않는 구조가 의도대로 작동하는지를 보여주는 결과입니다. 다만 RSS는 프로세스가 실제로 점유하는 메모리를 완벽하게 나타내는 값은 아니며, 이 수치는 특정 환경에서 측정한 참고값입니다.
